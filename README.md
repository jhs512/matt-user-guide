# Matt Pocock 스킬 실습 — 고등학교 공지사항 게시판을 배포까지

[기존 상세 문서 보기 (README v1)](README-v1.md)

**스킬 설치 → 프로젝트 설정 → 질문에 답하기 → 명세 작성 → 작업 나누기 → 구현·배포**

빈 프로젝트 폴더를 코딩 에이전트에서 열고 아래 순서대로 진행합니다. 설치 명령은 터미널에, `/`로 시작하는 요청은 프로젝트 대화창에 입력합니다.

## 1. 스킬 설치

Node.js와 Git이 설치된 환경에서 실행합니다.

```sh
npx --yes skills@latest add mattpocock/skills --global --skill "*" --agent codex claude-code --copy --yes
```

설치 후 코딩 에이전트를 완전히 종료하고 다시 실행합니다.

## 2. 프로젝트 설정 — /setup-matt-pocock-skills

프로젝트에서 사용할 작업 규칙과 문서 저장 위치를 정합니다. 처음 한 번만 실행합니다.

```text
/setup-matt-pocock-skills

고등학교 공지사항 게시판 프로젝트.
GITHUB 저장소 생성 후 연결해줘.
이슈와 명세는 로컬 Markdown.
triage는 기본 라벨을 사용.
AGENTS.md를 사용.
CLAUDE.md는 단순히 AGENTS.md를 가리키도록.
첫 커밋 전에 두 파일을 모두 만들고, CLAUDE.md에는 @AGENTS.md 한 줄을 넣어줘.
작업하면 커밋하고 바로 푸시해줘.
```

**확인:** GitHub 저장소가 연결되고, 첫 커밋에 두 지침 파일이 포함되어 있습니다.

## 3. 질문에 답하기 — /grill-with-docs

만들고 싶은 것을 말하고, 질문에 답하며 구체적인 기능과 구현 방식을 정합니다.

```text
/grill-with-docs

고등학교 공지사항 게시판을 만들고 배포까지 하고 싶어.
방문자는 목록과 상세를 보고, 관리자 한 명만 등록·수정·삭제해.
회원가입, 댓글, 첨부파일, 검색은 이번에는 빼자.

백엔드는 Spring Boot + Kotlin, 프론트엔드는 React + TypeScript로 생각하고 있어.
backend/와 frontend/ 폴더의 역할, DB, 인증, 배포 방식도 질문하며 정해줘.
필요한 기술·서비스 제약은 공식 문서로 확인해줘.
```

**확인:** 기능·권한·배포 방식과 완료 기준에 합의하고, 정한 내용이 문서에 남아 있습니다.

## 4. 명세 작성 — /to-spec

같은 대화에서 입력합니다. 앞 단계에서 합의한 내용을 구현 기준으로 정리합니다.

```text
/to-spec
```

**확인:** 무엇을 만들고, 무엇을 제외하며, 어떻게 테스트할지가 명세에 담겨 있습니다. 빠진 내용이 있으면 이때 수정합니다.

## 5. 작업 나누기 — /to-tickets

확인한 명세를 하나씩 구현하고 검증할 수 있는 작업으로 나눕니다.

```text
/to-tickets
```

**확인:** 각 작업의 완료 조건과 진행 순서가 정리되어 있고, 배포와 실제 동작 확인도 포함되어 있습니다.

## 6. 구현·배포 — /implement

```text
/implement

모든 티켓을 순서대로 구현하고 테스트해줘.
배포까지 진행하고, 배포된 주소에서 실제 동작을 확인해줘.
작업하면 커밋하고 바로 푸시해줘.
```

계정 연결이나 설정값 등 직접 처리할 일이 나오면 완료한 뒤 같은 대화에서 이어갑니다.

**완료 확인:** 배포된 주소에서 공지 목록·상세 조회와 관리자 등록·수정·삭제가 동작하고, 새로고침 후에도 데이터가 유지됩니다.

이후 새 기능을 추가할 때는 프로젝트 설정을 반복하지 않고 **질문에 답하기 → 명세 작성 → 작업 나누기 → 구현**으로 이어갑니다.
